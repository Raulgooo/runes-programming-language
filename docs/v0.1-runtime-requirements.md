# Runes v0.1 Compiler Runtime Contract

Status: implemented hosted-runtime ABI for the v0.1 C bootstrap.

This document defines only machinery required by generated Runes programs. It
does not define or request a standard library. Collections, files, sockets,
terminal policy, parsing, formatting APIs, threading, HTTP, numerical helpers,
and ML code remain user-owned library work.

The authoritative declarations are in `src/runtime.h`; the implementation is
`src/runtime.c` plus `src/utils/arena.c`. Generated programs normally link both.

## 1. Supported profile

v0.1 supports hosted Linux x86-64 through generated C11 compiled by GCC or
Clang. The runtime uses libc allocation and process I/O. A freestanding runtime
hook/profile is not implemented and must not be claimed by the compiler.

Generated-code ABI names use the reserved `runes_` prefix. Applications should
not define symbols with that prefix.

## 2. Compiler/runtime boundary

The compiler is responsible for:

- checked arithmetic and source-located trap calls;
- checked array, slice, and string bounds;
- realm-valid call and escape checking;
- arena scope entry/exit insertion on every control-flow exit;
- GC scope, frame, root, and temporary protection insertion;
- type-specific trace and deep-clone descriptors;
- closure wrapper and environment generation;
- fixed-array/slice representation and conversions;
- UTF-8 string literal construction;
- C declarations and ABI attributes.

The linked runtime is responsible for:

- trap reporting and process termination;
- raw aligned allocation;
- active regional arena trees;
- graph-preserving deep promotion;
- one precise scoped GC heap;
- length-bearing string/Unicode primitives;
- helper operations used by generated checks.

Neither layer supplies a general-purpose standard library.

## 3. Type descriptors

Generated code describes traversable values with:

```c
struct RunesTypeDescriptor {
  size_t size;
  size_t align;
  RunesCloneFunction clone;
  RunesTraceFunction trace;
};
```

`clone` deep-copies owned arena edges during promotion. `trace` visits GC edges
during marking. Generated descriptors cover pointer-bearing structs, variants,
arrays, slices, strings, interfaces, tuples, and closure environments. The
runtime also records repeated-element metadata for dynamically allocated typed
sequences and promoted slices.

Descriptors must never conservatively scan arbitrary bytes. Raw, borrowed,
external, and MMIO pointers are copied as values and are not recursively
claimed as owned arena edges.

## 4. Failure behavior

Generated checks and runtime invariants fail deterministically through
non-returning helpers embedded in generated C or implemented by the runtime.
Messages include the category, source line and column when available, and
relevant values.

Covered failures include:

- out of memory and invalid alignment;
- array, slice, and string bounds/range failures;
- UTF-8 scalar-boundary failures;
- integer overflow, division/remainder by zero, and invalid shifts;
- null-pointer unwrap;
- invalid Unicode scalar construction;
- missing active arena/GC scope and invalid GC-thread access.

Failure exits nonzero. The OOM path must not depend on another successful
allocation.

## 5. Raw allocation ABI

The runtime exports:

```c
void *runes_raw_alloc(size_t size, unsigned line, unsigned column);
void *runes_raw_alloc_aligned(size_t size, size_t align,
                              unsigned line, unsigned column);
void runes_raw_free(void *pointer);
```

Allocation traps on failure. Alignment must be a nonzero power of two. Size
and alignment arithmetic is checked. The Runes source intrinsics add source
locations automatically after declarations such as:

```runes
extern f raw_alloc(size: usize) = result: *void
extern f raw_alloc_aligned(size: usize, align: usize) = result: *void
extern f raw_free(pointer: *void)
```

Raw allocation is explicit ownership. The compiler does not insert
`raw_free`, track resource ownership, or detect double frees.

## 6. Regional arena ABI

```c
void *runes_arena_scope_enter(unsigned line, unsigned column);
void runes_arena_scope_leave(void *scope);
void *runes_alloc(size_t size, size_t align,
                  unsigned line, unsigned column);
void *runes_alloc_typed(size_t size, size_t align,
                        const RunesTypeDescriptor *descriptor,
                        unsigned line, unsigned column);
```

Each root `regional f` invocation creates an arena. Nested regional calls create
child arenas attached to the active parent. Child allocations remain alive
after the child call and are reclaimed recursively with the root. Scope exit is
emitted for fallthrough, explicit return, early return, and fallible
propagation.

Arena allocation provides checked alignment, checked growth, large-allocation
handling, and ownership metadata used by promotion. Debug counters expose live
scope/root counts for tests only.

Arena teardown frees memory only. It does not close files, sockets, mutexes, or
other external resources.

## 7. Deep promotion ABI

```c
void *runes_promote_dynamic(const void *source,
                            const RunesTypeDescriptor *descriptor,
                            unsigned line, unsigned column);
void *runes_promote_gc(const void *source,
                       const RunesTypeDescriptor *descriptor,
                       unsigned line, unsigned column);
```

The clone context maps old addresses to new addresses, preserving cycles and
shared aliases. It supports owned pointers, slices, strings, aggregates,
variants, interfaces, and closure environments. Promotion to `dynamic` creates
raw allocations; promotion to `gc` creates traced GC allocations.

Promotion is valid only for arena-derived ownership. Borrowed, raw, external,
MMIO, and existing GC data are not an alternate way to invoke this transfer.
The compiler rejects those uses.

The lower-level `runes_clone_value`, `runes_clone_pointer`,
`runes_clone_slice`, and `runes_clone_string` functions are descriptor support,
not user collection APIs.

## 8. Garbage collector ABI

v0.1 uses one process-wide precise, non-moving mark/sweep heap owned by one OS
thread. Multiple `gc f` declarations and calls share it on that thread.

Core ABI:

```c
void runes_gc_scope_enter(unsigned line, unsigned column);
void runes_gc_scope_leave(void);
void *runes_gc_frame_enter(unsigned line, unsigned column);
void *runes_gc_frame_enter_if_active(unsigned line, unsigned column);
void runes_gc_frame_leave(void *frame);
void *runes_gc_root_push(void *value,
                         const RunesTypeDescriptor *descriptor,
                         unsigned line, unsigned column);
void runes_gc_root_freeze(void *root, unsigned line, unsigned column);
void *runes_gc_alloc(size_t size, size_t align,
                     const RunesTypeDescriptor *descriptor,
                     unsigned line, unsigned column);
void runes_gc_collect(void);
```

The compiler emits shadow-stack frames and exact roots. `freeze` protects the
last value of a binding after its lexical storage is no longer updated.
`runes_gc_protect_value` keeps returned/intermediate values alive across frame
teardown; `runes_gc_commit_allocations` closes the temporary-allocation window.

Collection happens synchronously only on an allocation threshold/slow path or
explicit `runes_gc_collect`. There are no asynchronous signals, timer polls,
loop polls, read barriers, or write barriers. Marking uses an explicit worklist,
not recursive native-stack traversal. Sweep releases unreachable tracked
objects.

GC limitations:

- one owning OS thread; GC references may not cross threads;
- no finalizers, weak references, public free, generations, compaction,
  incremental marking, or concurrent marking;
- no language-level public root-handle facility for arbitrary foreign/raw
  retention;
- current call rules prevent regional code from reaching GC safepoints, so
  arenas do not need to be scanned as GC root containers.

`RunesGcStats`, `runes_gc_stats`, threshold setters, and debug counters exist
for runtime tests and diagnostics. They are not a stable standard-library API.

## 9. String and Unicode ABI

```c
typedef struct RunesStr {
  const uint8_t *ptr;
  size_t len;
} RunesStr;
```

`str` is an immutable byte view containing valid UTF-8. It is not implicitly
NUL-terminated, and embedded NUL bytes are valid.

Runtime operations:

- `runes_str_equal` and `runes_str_compare`: length-aware byte operations;
- `runes_str_concat`: checked allocation in the active realm;
- `runes_str_byte_at`: checked byte indexing;
- `runes_str_slice_bytes`: checked ranges and optional UTF-8 boundaries;
- `runes_str_is_utf8` and `runes_str_is_scalar_boundary`: validation;
- `runes_str_decode_next` and `runes_utf8_encode`: scalar iteration/encoding;
- `runes_char_from_u64`: checked Unicode scalar construction;
- `runes_str_hash`: deterministic byte hash;
- `runes_str_from_bytes` and `runes_str_from_c_checked`: validated views;
- `runes_str_to_c`: allocated NUL-terminated interoperability buffer;
- `runes_str_write_stdout` and `runes_char_write_stdout`: compiler `print`
  support.

`runes_str_to_c` returns raw allocated storage and the caller must release it
with `runes_raw_free`. Higher-level owning strings, builders, normalization,
case conversion, parsing, and formatting are standard-library work.

## 10. Source-level runtime declarations

`src/std/prelude.runes` declares the currently required runtime functions for
ordinary programs. It contains no collections or platform library. Use it with:

```bash
./runec build --prelude app.runes -o build/app
```

Programs may instead declare only the exact extern contracts they use. The
compiler recognizes `alloc`, `raw_alloc`, `raw_alloc_aligned`, `raw_free`, and
selected C memory/math names specially when lowering, but name resolution still
requires a declaration.

The compiler builtin `print`, syntax forms `sizeof`, `alignof`, and `promote`,
checked indexing/arithmetic, and closure invocation do not need prelude
declarations.

## 11. Build contract

The supported direct link command is equivalent to:

```bash
gcc -Isrc -std=c11 generated.c src/runtime.c src/utils/arena.c -lm -o program
```

`runec build` performs this step. Additional C libraries or object files belong
after `--`. The runtime itself has no package manager or dependency resolver.
Filesystem `mod` discovery is performed by the compiler before C generation.

## 12. Acceptance gates

Runtime changes must keep these gates green:

```bash
make test-unit
make test-core
make test-codegen
make test-runtime-sanitize
make test-sanitize
make fuzz-smoke
```

Coverage includes alignment and arena ownership, early/fallible cleanup, deep
graph promotion, cycles and aliases, slice/string/closure promotion, GC graphs
and typed sequences, temporary roots, UTF-8 and embedded NUL, deterministic
string/Unicode property tests, bounds/arithmetic traps, generated-C
differential execution, and ASan/UBSan runs.

## 13. Explicitly outside this runtime

Do not add these to the compiler runtime merely to reach v0.1:

- vectors, maps, sets, options, string builders, or slice algorithms;
- file, path, terminal, process, socket, HTTP, or scanner APIs;
- general formatting beyond the compiler's primitive `print` support;
- thread abstractions or synchronization;
- tensor, BLAS, numerical, training, inference, or ML facilities;
- application resource management or a cleanup/defer framework.

Those facilities can be authored in Runes or exposed through explicit FFI by
the user-maintained standard library.
